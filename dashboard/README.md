# SPVX-Lite Dashboard

Production-ready single page application that consumes the FastAPI endpoints exposed by `spvx-lite`. The goals:

- Visualise SPVX-Lite index history and daily change.
- Surface spread-direction and throughput signals with contextual drivers.
- Provide live health + latency indicators to reflect `/ready` and `/metrics`.
- Prepare for go-live with environment-based configuration, caching, and deployment automation.

## Architecture Overview

| Layer | Choice | Notes |
|-------|--------|-------|
| Build tool | [Vite](https://vitejs.dev/) | Fast HMR, TS-first. |
| Runtime | React 18 + TypeScript | Common SPA stack. |
| Data fetching | [TanStack Query](https://tanstack.com/query) | Caching, revalidation, retries → easy to add stale-while-revalidate. |
| Visualisation | [Recharts](https://recharts.org/) | Light, composable charts; easy theming. |
| Styling | Tailwind CSS + CSS variables | Utility-first; supports dark mode toggle. |
| State | Minimal React context (for API base URL, theme) + Query cache. |
| Quality | ESLint + Prettier + Vitest + Playwright smoke. |

## Feature Map (MVP)

1. **Index Overview**
   - Area/line chart of SPVX-Lite (last 90 vs 365 days toggle).
   - Daily change sparkline, latest value card with delta vs prior day.
   - Heatmap of component z-scores (CQ_TR / CQ_SG / PORT_EU).
2. **Signals Panel**
   - Spread-direction card: probability, top-decile tag, optional scenario text.
   - Throughput nowcast table: predicted vs actual (if available), MAE gauge.
   - Drivers list with icons (weather, chokepoints, etc.) derived from `signals.json`.
3. **Operations**
   - Status bar reading `/health` + `/ready`.
   - Metrics micro-chart (requests, job durations) from Prometheus via `/metrics`.
   - Run meta info (git SHA, timestamp) from `run_meta.json`.
4. **UX**
   - Dark/Light mode.
   - Refresh cadence indicator (auto refresh with manual force).
   - Error boundary with “degraded mode” message if `degraded=true`.

## Data Flow

```
TanStack Query → API clients → FastAPI endpoints
    ↳ useIndexSeriesQuery() -> /spvx-lite
    ↳ useSpreadSignalsQuery() -> /spread-signals
    ↳ useThroughputNowcastQuery() -> /throughput-nowcast
    ↳ useSignalsSnapshotQuery() -> /signals.json (served by backend)
    ↳ useHealthQuery() -> /ready /health
```

All queries share a `baseUrl` read from `VITE_API_BASE_URL` and fallback to `http://localhost:8081`.

## Environments

- `development`: local Vite dev server (port 5173).
- `staging` / `production`: static build served behind CDN (e.g., CloudFront, Netlify).
- Configuration via `.env.[mode]` files that define `VITE_API_BASE_URL`, `VITE_REFRESH_SECONDS`, `VITE_ENABLE_METRICS`.

## Deployment Pipeline

1. `pnpm install` (preferred) or `npm install`.
2. `pnpm build` → generates static assets under `dist/`.
3. `pnpm preview` for smoke, `pnpm test` (Vitest), `pnpm lint`.
4. CI: GitHub Actions with caching, pushes to S3/Netlify (placeholder).

## Getting Started

```bash
cd dashboard
cp .env.example .env               # adjust VITE_API_BASE_URL if backend runs elsewhere
pnpm install                       # or npm install
pnpm dev                           # launches on http://localhost:5173
```

Back-end expects the FastAPI service (from `spvx-lite`) running locally — set `VITE_API_BASE_URL` accordingly (e.g. `http://localhost:8081`).

## Quality Gates

- `pnpm lint` for ESLint (`.eslintrc.cjs`).
- `pnpm test` for Vitest (`vitest.config.ts`, jsdom environment).
- `pnpm build` must succeed; CI step can deploy `dist/` to CDN/S3.
- Optional metrics pull (`/metrics`) is gated by `VITE_ENABLE_METRICS`.

## Deployment Notes

- The build artefacts are static; serve behind CDN or containerise with Nginx.
- Provide environment variables through `.env.production` or platform secrets.
- Enable HTTP caching (immutable fingerprinted assets generated by Vite).
- CSP suggestion: restrict to `self` plus backend origin for fetch calls.
